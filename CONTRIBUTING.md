# Contributing

H.U.M.A.N. Protocol is an open working draft. Contributions are welcome when they make the language clearer, more practical, more inclusive, or easier to test against real experiences.

## Good Contributions

- Better examples from real domains.
- Clearer schema fields.
- Accessibility improvements.
- Evidence and source mapping.
- Comparisons to existing standards.
- Critiques that identify where the model is too broad, vague, redundant, or hard to maintain.
- New principles only when they change how people use the protocol.

## Contribution Style

Prefer concrete improvements over broad declarations.

Before adding a new concept, ask:

- Does this help someone describe an experience more clearly?
- Does this help an AI system reason with less guesswork?
- Does this preserve human agency, accessibility, or evidence quality?
- Can this be shown in an example?
- Is this already handled better by an existing standard?

## What To Avoid

- Do not replace established standards with local paraphrases.
- Do not turn the protocol into a compliance checklist.
- Do not add fields that are only decorative.
- Do not reduce people to static personas.
- Do not make AI the center of the human experience.
- Do not add tooling before the language is useful.

## Drafting Rules

- Use plain language.
- Prefer examples.
- Label assumptions.
- Distinguish standards, research, policy, design preference, and hypothesis.
- Keep schema fields broad enough for multiple domains, but specific enough to be useful.
